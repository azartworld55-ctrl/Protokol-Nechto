# AzartWorld — библиотека модов RimWorld

Репозиторий развивается из проекта «ПРОТОКОЛ: НЕЧТО» в общую библиотеку и набор отдельных модов для **RimWorld 1.7 Android / Ports1de Beta 14**.

Каждый мод — самостоятельный проект со своими механиками и настройками. Общий код выносится в библиотеку только тогда, когда он действительно нужен нескольким модам.

## Проекты

### Тюремная колония (рабочее название: Prison Colony)

Новый приоритетный проект. Игрок управляет тюрьмой: строит камеры и инфраструктуру, организует распорядок, принимает заключённых, управляет персоналом, безопасностью, снабжением и реагирует на происшествия и попытки побега.

- [Концепция и план первой версии](docs/ТЮРЕМНАЯ_КОЛОНИЯ.md)

### ПРОТОКОЛ: НЕЧТО

Отложенный самостоятельный проект: социальная симуляция в исследовательской базе и скрытый паразит. Существующие документы и наработки сохраняются.

- [Старая концепция](docs/КОНЦЕПЦИЯ.md)
- [Старый план разработки](docs/ПЛАН.md)
- [Конфигурация квот профессий](docs/КОНФИГУРАЦИЯ_ПРОФЕССИЙ.md)

## Общая библиотека

Планируемое имя: `AzartWorld.Core`.

Предполагаемые общие функции:
- общие настройки и конфигурация модов;
- общие вспомогательные классы и диагностика;
- общие механизмы сохранения данных, если они действительно повторяются;
- общие адаптеры совместимости с Ports1de.

Библиотека не должна превращаться в обязательную зависимость для каждого мода без необходимости. Игровые механики конкретного проекта остаются внутри него.

## Целевая платформа и ограничения

- RimWorld 1.7.
- Android-порт Ports1de Beta 14.
- Совместимость ПК-модов не считается доказательством совместимости с Ports1de.
- Поддержка каждой функции подтверждается сборкой и проверкой на целевой версии игры.
- До появления рабочего тестового мода API, Harmony, загрузка DLL, UI и сохранения считаются областями проверки, а не гарантированными возможностями.

## Принцип разработки

Сначала небольшой вертикальный прототип, который можно загрузить и проверить в игре. Затем — расширение механик. Не строим огромную абстрактную библиотеку заранее: общую архитектуру выделяем из работающих и повторно используемых решений.
