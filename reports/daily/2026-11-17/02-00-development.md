## Что реально реализовано

- Добавлен `ProfessionRosterComposer`: он принимает уже созданный упорядоченный список жителей, проверенную конфигурацию квот, seed и callback, который возвращает копию жителя с назначенной профессией.
- Composer проверяет количество жителей и после материализации перечисления, отклоняет null-элементы и callback, возвращающий null.
- Каждому жителю назначается ровно один элемент из результата `ProfessionQuotaAllocator`; порядок жителей сохраняется.
- Возвращается read-only коллекция. Сам composer не меняет входную коллекцию и не зависит от типа жителя.
- Добавлены тесты точных количеств по каждой квоте, сохранения ID/имён/порядка, неизменности исходных record-объектов, повторяемости полного ростера при одинаковом seed, read-only результата, неверного размера, null-элементов и некорректного callback.
- Обновлены документация модуля квот, архитектура и план.

**Граница результата:** это законченный generic API для применения квот к уже сгенерированным 12 жителям. ## Архитектурные решения

- Квоты по-прежнему задаются только явной JSON-конфигурацией. Значения из тестовой fixture синтетические и не являются игровым балансом.
- Composer использует существующий детерминированный allocator, а не `System.Random`.
- Callback отвечает за создание нового значения жителя. Для mutable-класса вызывающий код обязан не изменять входной объект; generic API не может технически гарантировать глубокую неизменяемость произвольного `TResident`.
- Не добавлялись RimWorld, Verse, Unity, Harmony или Ports1de ссылки, UI, загрузчик файла из каталога мода и игровые хуки.
- Mobile-first сенсорный интерфейс остаётся обязательным требованием к будущему адаптеру, но пока не реализован: UI API конкретной сборки Ports1de не подтверждён.
