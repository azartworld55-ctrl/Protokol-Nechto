## Найденные ошибки и исправления

### 1. Отношения были направленными

Исходный контракт 02:00 хранил A→B отдельно от B→A. Это противоречило требованию этапа: доверие и знакомство должны быть симметричны.

Исправлено в `RelationshipLedger`: ключ строится для неупорядоченной пары Guid. `Get(A, B)` и `Get(B, A)` возвращают один и тот же неизменяемый `RelationshipState`; `Adjust` с любой стороны изменяет общую запись. Trust и Familiarity остаются независимыми шкалами 0–100. Насыщение до границ по-прежнему безопасно для `long.MinValue` и `long.MaxValue`.

### 2. Чтение журнала памяти каждый раз копировало всю коллекцию

`MemoryJournal.Entries` создавал новый массив и read-only wrapper при каждом чтении. При частом опросе это давало лишние O(n) копирования и выделения памяти.

Добавлен кеш неизменяемого снимка. Запись или замена инвалидирует кеш; уже выданный снимок не меняется. Модель по-прежнему рассчитана на последовательное обновление, не на конкурентный доступ из нескольких потоков.

### 3. Услышанный слух не повышался до прямого знания

Ранее дедупликация event ID безусловно отклоняла последующее прямое наблюдение. Житель, который услышал слух, а затем сам подтвердил то же событие, навсегда оставался с пометкой HeardRumor.

Исправлено:
- `DirectObservation` теперь различает `EventTick` и `ObservedAtTick`; прежний конструктор с одним tick сохранён как совместимый вариант.
- Если владелец журнала непосредственно подтверждает тот же event ID, subject и event tick позже момента получения слуха, запись заменяется на `DirectObservation`.
- При повышении сбрасываются происхождение слуха и затухание достоверности; исходный event tick сохраняется, learned-at tick отражает фактическое время подтверждения.
- Нельзя задним числом подтвердить слух временем раньше его получения; повтор event ID для другого subject/event tick отклоняется.
- Ранее выданные снимки остаются неизменными.

### 4. Конструктор MemoryEntry допускал противоречивые состояния

Добавлены проверки инвариантов:
- прямое наблюдение не содержит source conversation, имеет confidence 1000, retell count 0 и одного observer/informant;
- слух обязан содержать ненулевой ID разговора, положительный retell count и положительную достоверность;
- event ID, tick, confidence и enum остаются ограниченными.
