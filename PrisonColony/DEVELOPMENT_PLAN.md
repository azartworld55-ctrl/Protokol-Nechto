# Prison Colony — план реализации

**Цель:** RimWorld 1.7 / Ports1de Beta 14.  
**Принцип:** сначала подтвердить загрузку и сохранения на целевом Android-порте, затем строить игровые системы.

## Текущее состояние

Создан самостоятельный каталог мода `PrisonColony/` с About.xml, проектом C# и первыми классами.
Загрузочный класс выводит сообщение в лог. `PrisonColonyGameComponent` хранит списки контрактов и записей заключённых через штатный Scribe.

Это исходный каркас, а не готовая игровая версия: DLL ещё не собрана против библиотек целевой установки, запуск в Ports1de и round-trip сохранений ещё не проверены.

## Этап 0 — подтверждение среды

Нужно зафиксировать для Ports1de Beta 14:
- фактический Target Framework и доступную версию Mono/.NET;
- наличие и версии `Assembly-CSharp.dll`, `Verse.dll` и Unity-модулей;
- поддерживаемый способ загрузки DLL из `Assemblies`;
- поведение GameComponent и Scribe в сохранениях;
- ограничения UI и событий, специфичные для Android-порта.

Не подменять эти сведения предположениями о стандартной PC-сборке RimWorld.

## Этап 1 — загрузочная версия

Критерии:
1. Мод виден в списке модов.
2. About.xml читается без ошибок.
3. DLL загружается без MissingMethodException / TypeLoadException.
4. В логе есть сообщение Prison Colony.
5. Новая игра и загрузка существующего сохранения проходят без ошибок.

## Этап 2 — проверка собственных данных

Добавить тестовую запись заключённого и контракт в GameComponent, сохранить игру, полностью перезапустить её и загрузить сохранение.
Проверить:
- восстановление ссылок на Pawn;
- сохранение ID и срока контракта;
- отсутствие null-списков после PostLoadInit;
- отсутствие дублирования записей при повторной загрузке.

Пока эта проверка не пройдена, не наращивать объём сохраняемых данных.

## Этап 3 — первый контрактный цикл

Состояния контракта:
- Offered — предложение доступно игроку;
- Accepted — принято, ожидается прибытие;
- Active — заключённые размещены, срок идёт;
- Completed — срок завершён;
- Departing — заключённые ожидают отправления;
- Closed — отправление завершено;
- Failed — контракт нарушен или отменён.

Переходы:
1. Создать предложение с размером партии, сроком 1–30 дней и дневной ставкой.
2. При принятии проверить свободную вместимость.
3. Создать прибывающих пешек безопасным способом, подтверждённым API Ports1de, и зарегистрировать их.
4. Начать отсчёт только после фактического приёма.
5. Начислять оплату за прошедшие игровые сутки.
6. По окончании срока сформировать отправление и завершить записи после подтверждённого удаления/отбытия пешек.

На первом проходе транспорт может быть представлен событием прибытия/отправления в терминальной зоне, если API шаттлов недоступен. Это не должно маскироваться под настоящую посадку шаттла.

## Этап 4 — тюремные предметы и системы

Добавлять по одной проверяемой функции:
- простая камера и кровать;
- терминал/объект регистрации;
- камера наблюдения и зона покрытия;
- монитор, подключение и питание;
- электронная дверь и сигнализация;
- назначение охраны и режимы безопасности.

Предметы должны иметь реальные игровые свойства и понятную стоимость. Декоративные объекты без механики не считать реализованными.

## Этап 5 — симуляция и кризисы

После стабильного цикла контрактов:
- расписание и режимы;
- настроение и социальные связи;
- категории заключённых;
- инспекции и репутация;
- абстрактная напряжённость и побеги;
- внешние налёты, саботаж и природные угрозы.

Налёты и побеги — игровые события высокого уровня, не отдельная тактическая или реалистичная инструкция по проникновению/обходу охраны.

## Правила качества

- Каждая новая система должна сохраняться и восстанавливаться.
- Не добавлять API Harmony или транспортные вызовы без проверки их наличия в Ports1de Beta 14.
- Не заявлять о сборке или тесте, пока они фактически не выполнены.
- Android-производительность важнее фоновой симуляции каждого заключённого каждый тик.
