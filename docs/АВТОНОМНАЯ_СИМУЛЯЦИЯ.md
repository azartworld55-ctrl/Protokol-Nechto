# Автономная симуляция жителей

Статус: независимый доменный модуль в ветке `daily/2026-11-21`.

## Назначение

`Protocol.Autonomy` задаёт проверяемую модель почасового выбора абстрактных действий для фиксированной станции из 12 жителей. Модуль не управляет игровыми объектами и не предполагает наличие API RimWorld, Unity, Harmony или Ports1de.

## Контракты

- `NeedState`: четыре шкалы неудовлетворённых потребностей — голод, усталость, общение и стресс — в диапазоне 0..1000.
- `NeedDelta`: знаковые изменения за один час. Положительное значение увеличивает неудовлетворённость, отрицательное уменьшает её; результат насыщается на границах без переполнения.
- `DailySchedule`: повторяющиеся минутные интервалы. Интервал может пересекать полночь; конец не включён; незаполненные минуты означают свободное время; пересечения запрещены.
- `ResidentAutonomyProfile`: стабильный `ResidentId`, внешний ID профессии, общительность, дисциплина и список habit ID. Это минимальный контракт; адаптер может отобразить на него полный профиль из будущего/отдельного `Protocol.Core`.
- `StationAutonomyState`: ровно 12 уникальных жителей, упорядоченных по стабильному ID, и минута текущих суток.
- `AutonomyPolicy`: обязательные пороги и приоритеты для четырёх потребностей, необязательная привязка порога к одной из двух личностных осей, предпочтения привычек, почасовые изменения для каждого действия и минимальные отношения для выбора собеседника.

## Почасовой переход

`StationAutonomySimulator.AdvanceHour` выполняет строго определённую последовательность:

1. Применяет к каждому жителю эффект его предыдущего действия из конфигурации.
2. Переводит часы на 60 минут с переходом через полночь.
3. Проверяет потребности в порядке явных приоритетов политики. Срочная потребность может прервать расписание.
4. Если срочной потребности нет, выбирает действие из текущего расписания.
5. В свободное время и досуговом интервале применяет первую подходящую привычку по настроенному приоритету.

Работа возможна только в блоке `Work`; рабочее намерение содержит исходный profession ID жителя. Модуль не назначает квоты и не придумывает названия профессий.

Социальное намерение выбирает допустимого партнёра по знакомству, затем доверию, затем стабильному ID. Если подходящего партнёра нет, цель остаётся пустой. Результат — только намерение; он не создаёт `ConversationEvent` и не доказывает физическую достижимость.

## Баланс и детерминизм

В модуле нет встроенных игровых порогов, скоростей изменения потребностей, квот профессий или расписаний. Все эти значения поступают через обязательный `AutonomyPolicy` и данные жителей. Числа в тестах — синтетические fixtures, не утверждённый баланс.

Симуляция не использует генератор случайных чисел: одинаковое начальное состояние, порядок событий, политика и отношения дают одинаковый результат. Жители нормализуются по стабильному ID.

## Границы

- Модуль зависит только от `Protocol.Social` ради `ResidentId` и `RelationshipLedger`; он не зависит от `Protocol.Core`, потому что Core и его интеграция пока находятся в отдельном Draft PR #6, а не в `main`.
- Рабочее действие пока не превращается в реальную RimWorld job, не проверяет рабочее место, путь, ресурсы или доступность помещения.
- Социальное действие пока не создаёт разговор и не меняет отношения; физический контакт должен подтвердить отдельный слой восприятия.
- Нет сохранения через Scribe, игрового адаптера, HUD или сенсорного интерфейса.
- Параллельное выполнение не заявляется; симулятор рассчитан на последовательный вызов одного шага.

## Проверки

`tests/Protocol.Autonomy.Tests` проверяет границы потребностей, насыщение при экстремальных delta, расписание через полночь, пересечения блоков, ровно 12 жителей, уникальность ID, приоритет срочных потребностей, личностные пороги, работу только в смену, привычки, выбор социального намерения и воспроизводимость 72-часового прогона.
