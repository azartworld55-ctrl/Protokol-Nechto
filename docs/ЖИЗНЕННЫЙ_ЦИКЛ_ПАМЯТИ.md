# Жизненный цикл личной памяти

Дата: 22 ноября 2026 года (Europe/Moscow)

## Назначение

`Protocol.Social` хранит личные наблюдения и услышанные слухи. Без ограничений журнал мог бы расти всю партию, а затухание слуха нельзя смешивать с тем, насколько хорошо житель помнит сам факт получения информации.

Новая модель разделяет три величины:

- `ConfidencePermille` — насколько достоверным житель считает слух. У прямого наблюдения значение всегда 1000.
- `RecallStrengthPermille` — насколько хорошо житель способен вспомнить запись. Именно эта шкала затухает со временем.
- `ImportancePermille` — заданная вызывающим слоем важность для сохранения при переполнении.

Затухание воспоминания не превращает достоверное наблюдение в ложное и не меняет уверенность в слухе.

## Явная политика

`MemoryLifecyclePolicy` не имеет игровых значений по умолчанию. Вызывающий слой обязан передать:

| Параметр | Смысл |
|---|---|
| `RecallDecayPerTickPermille` | линейная потеря силы воспоминания за один tick |
| `ForgetBelowRecallStrengthPermille` | порог силы, при котором запись может быть забыта |
| `MinimumAgeBeforeForgettingTicks` | минимальный возраст записи |
| `MaximumEntries` | предельное число активных записей журнала |

Домен не знает, сколько игровых или реальных секунд соответствует одному tick. Отрицательные значения и ёмкость меньше единицы отклоняются.

## Обновление журнала

`MemoryLifecycleService.Advance(journal, currentTick, policy)`:

1. Проверяет, что время не отрицательно и не движется назад относительно любой записи.
2. Рассчитывает линейное затухание силы воспоминания от последнего `LastEvaluatedTick`.
3. Забывает запись только когда одновременно выполнены минимальный возраст и порог силы (включительно).
4. Если записей больше ёмкости, вытесняет их в детерминированном порядке: важность по возрастанию, сила памяти по возрастанию, время получения по возрастанию, EventId.
5. Возвращает число просмотренных, затухших, забытых, вытесненных и оставшихся записей.

Умножение elapsed ticks на скорость затухания ограничивается до умножения, поэтому `long.MaxValue` не вызывает переполнения. Повторный вызов на том же tick не применяет затухание повторно. Журнал хранит последний обработанный tick даже после удаления всех записей и отклоняет движение времени назад или позднее добавление записи из прошлого.

## Подтверждение слуха

Если владелец журнала позже непосредственно наблюдает то же событие с теми же EventId, SubjectId и EventTick, существующий `MemoryJournal.RecordObservation` повышает слух до прямого наблюдения:

- `Kind` меняется на `DirectObservation`;
- `ConfidencePermille` и `RecallStrengthPermille` становятся 1000;
- источником знания становится сам наблюдатель;
- важность не уменьшается: сохраняется максимум прежней и новой оценки;
- старые read-only snapshots не меняются.

Домен не подтверждает событие автоматически и не делает выводов из чужой памяти.

## Приватность и границы

- Сервис получает ровно один `MemoryJournal` и не может перечислить журналы станции.
- Записи остаются неизменяемыми; обновление создаёт новую запись.
- Выданные ранее snapshots не изменяются даже после забывания.
- Политика должна вызываться последовательно для одного журнала. Потокобезопасность не заявляется.
- Архив удалённых записей не создаётся: забытая или вытесненная запись удаляется из активного журнала.
- Сериализация, сохранение через RimWorld Scribe и восстановление после загрузки пока не реализованы.

## Проверки

Регрессионные проверки охватывают раздельное затухание памяти и достоверности слуха, идемпотентность одного tick, прямое подтверждение слуха, возрастной порог забывания, ограничение ёмкости, детерминированный порядок вытеснения, неизменность старых snapshots, движение времени назад и границы `long.MaxValue`.

Все численные политики в тестах — синтетические fixtures, не утверждённый игровой баланс.
