# Ports1de Beta 14 — сохранённая техническая база проекта

Дата фиксации: 16 ноября 2026 года  
Рабочая ветка: \`feature/initial-social-core\`  
Полный технический журнал и история инструментов: [PROJECT-KNOWLEDGE-SNAPSHOT.md](https://github.com/azartworld55-ctrl/Ports1de-technical-files/blob/main/docs/ports1de-beta14/PROJECT-KNOWLEDGE-SNAPSHOT.md)

## Целевая среда

- Ports1de Beta 14, Android, RimWorld 1.7.
- Внутренняя игровая сборка: \`Assembly-CSharp.dll\`, версия \`1.7.9795.32073\`, целевой framework по предыдущему inventory: \`.NETCoreApp,Version=v10.0\`.
- Harmony: \`0Harmony.dll\`, версия 3.0.0.0.
- В порте присутствуют отдельные \`PortUI.dll\`, \`ModCompatibility.dll\`, \`Waylith.UnityCompat.dll\`, \`UnityStubs.dll\` и \`Waylith.dll\`.
- Наличие этих сборок не означает автоматическую совместимость произвольных PC-модов.

## Что показал анализ

### Мобильное управление

В \`PortUI.dll\` обнаружены:
- \`MobileTouchInput\` — обработка/очередь сенсорных команд;
- \`MobileSelectionController\` — выбор объектов и пешек касанием;
- \`QuickOrderWheel\` — круговое меню приказов;
- \`TouchGestureEngine\` — обработка сенсорных жестов;
- преобразование координат UI в координаты карты через \`UIToMapPosition\`.

Решение: интерфейс «ПРОТОКОЛ: НЕЧТО» нужно подключать к существующей мобильной системе, не создавать конкурирующий слой управления без необходимости.

### Подготовка модов

В \`ModCompatibility.dll\` найдены \`ModPreparer\`, \`ModAssemblyImageLoader\`, \`UnityApiPolyfillBridge\`, \`ModArchiveInstaller\`, \`ModCatalog\`, \`ModPreparationCache\`, \`ModListSanitizer\`, \`VfsCaseInsensitiveHook\` и \`MobileTexturePreprocessor\`.

Упоминания Mono.Cecil в CIL указывают на механизм анализа/преобразования сборок. Это не является доказательством поддержки всех модов или всех Harmony-патчей.

### Unity-совместимость

\`Waylith.UnityCompat.dll\` содержит собственные типы/методы для объектов, компонентов, Transform, ресурсов и lifecycle-сообщений. \`UnityStubs.dll\` содержит обширный набор UnityEngine-типов и backend-интерфейсов, но не содержит Verse/RimWorld/Pawn/Map API.

Следовательно, реальные игровые точки интеграции следует искать в \`Assembly-CSharp.dll\`, а не выводить из наличия Unity stubs.

### Harmony

Присутствует Harmony 3.0.0.0 с Harmony API и механизмами Prefix/Postfix/Transpiler/Finalizer. Совместимость конкретных патчей должна проверяться на точных методах и в runtime.

## Что уже есть в коде мода

Реализовано в core/domain слое: жители, память, отношения, расписания, потребности, автономные решения, социальные контакты, слухи, обзор/LOS, расследования, доказательства, подозрение, последствия обвинений, состояние задержания и логика решений паразита.

Существует отдельный RimWorld adapter проект с Verse.Mod entry point, инициализацией Harmony и диагностикой версий. Есть реестры runtime ID, построитель снимка карты и мост инцидентов, но они пока не подключены к живым событиям игры.

## Что пока НЕ подтверждено

- Успешная сборка адаптера против DLL именно этой Beta 14.
- Успешная загрузка мода на устройстве.
- Живые Harmony gameplay hooks.
- Подписка на реальные события Pawn/Map/Tick/Job.
- Настоящий мобильный HUD, выбор управляемой пешки и следящая камера.
- Реальная смена имени/внешности/социальной роли пешки после копирования.
- Интеграция сохранений через Scribe.
- Полноценное игровое задержание, охрана, камеры и побег.

## Текущая проверка

В техническом репозитории расширен workflow:
- рекурсивная инвентаризация вложенных архивов;
- анализ всех обнаруженных managed DLL;
- сбор зависимостей сборок и индекса игровых API;
- расширенный IL-анализ \`Assembly-CSharp.dll\`;
- отдельный отчёт по нативным библиотекам и конфигурациям.

На момент записи пользователь сообщил, что workflow выполняется. Результаты нового запуска ещё не получены и не должны считаться подтверждёнными до чтения отчётов.

## Следующие технические шаги

1. Прочитать новый \`DEEP-STATIC-AUDIT.md\` и обновлённый \`PORTS1DE-IL-ANALYSIS.md\`.
2. Найти конкретные методы Verse/RimWorld для Pawn, Map, Tick, Job, UI и Scribe.
3. Разобрать \`ModPreparer\`, \`UnityApiPolyfillBridge\`, \`ModAssemblyImageLoader\` и последовательность загрузки.
4. Найти безопасные точки интеграции в PortUI.
5. Сопоставить API с кодом адаптера и собрать минимальный runtime probe.
6. Проверить фактическую загрузку на устройстве; только после этого считать платформенную совместимость подтверждённой.

## Правило достоверности

Разделять:
- **метаданные** — тип/метод существует в сборке;
- **CIL** — подтверждено содержимое тела метода;
- **гипотеза** — предполагаемое назначение по именам/вызовам;
- **runtime-тест** — поведение воспроизведено в точной версии Ports1de на устройстве.

Не выдавать наличие API за доказательство работоспособности.
