# Проверка Ports1de Beta 14

Статус: подготовительный чек-лист. Целевая версия для первой практической проверки — Ports1de Beta 14, которую пользователь устанавливает. До теста на устройстве ни один пункт ниже не считается подтверждённым.

## Что уже известно

- Порт предоставляет отдельный импорт модов, включение модов и перезапуск игры после каждого шага.
- Разработчик Ports1de предупреждает, что совместимость отдельных модов не гарантируется.
- В объявлении Beta 11 заявлена поддержка модов после переноса движка на Android, но это не доказывает совместимость конкретной DLL, Harmony-патча или версии runtime.
- Установка мода через меню Ports1de сама по себе не подтверждает, что его DLL успешно загружается и что все используемые API доступны.

## Что нужно выяснить в Beta 14

### Версия и среда
- [ ] Точное отображаемое название и номер сборки Ports1de.
- [ ] Версия RimWorld, которую сообщает игра.
- [ ] Версия Verse API из фактически загруженной игровой сборки.
- [ ] Имя, версия и расположение Harmony DLL, если она присутствует.
- [ ] Какой runtime используется для загрузки модовых DLL: Mono, .NET или собственная/изменённая среда.
- [ ] Архитектура процесса и ограничения Android, влияющие на загрузку сборок.

### Формат мода
- [ ] Какой архивный формат принимает импортёр и сохраняет ли структуру каталогов.
- [ ] Где порт размещает импортированный мод.
- [ ] Как выглядит ожидаемая структура папок мода.
- [ ] Какие поля About.xml обязательны для определения мода.
- [ ] Загружаются ли DLL из стандартного каталога 1.7/Assemblies.
- [ ] Требуется ли отдельное разрешение или действие для модов с DLL.
- [ ] Где находятся логи загрузки модов и как их извлечь.

### Минимальные тесты
- [ ] Запустить игру без сторонних модов и сохранить исходный лог.
- [ ] Проверить простой XML-only мод без DLL.
- [ ] Проверить минимальную DLL-сборку без Harmony-патчей.
- [ ] Проверить минимальную сборку с Harmony только после подтверждения версии Harmony.
- [ ] Проверить повторный запуск после включения мода.
- [ ] Проверить, что ошибка одного мода не повреждает сохранение и не блокирует запуск игры.

## Что собрать для диагностики

1. Скриншот экрана версии Ports1de.
2. Скриншот списка включённых модов.
3. Структуру каталогов импортированного тестового мода.
4. Лог запуска после включения тестового мода.
5. Имена и версии игровых/Harmony DLL, если файловый доступ это позволяет.

Не публиковать личные файлы, токены, аккаунтные данные или полные каталоги игры. Для диагностики достаточно названий файлов, версий, структуры каталогов и релевантного фрагмента лога.

## Правило принятия решений

Пока Beta 14 не проверена, не менять TargetFramework, Harmony reference и сигнатуры Verse API на основании предположений. Текущий проект Protocol.RimWorld использует net10.0 и внешние ссылки на Assembly-CSharp.dll/0Harmony.dll как предварительную конфигурацию, а не как подтверждённое требование Ports1de.

После получения фактических данных:
1. Зафиксировать точные версии и пути DLL.
2. Сверить их с TargetFramework и Harmony reference.
3. Собрать минимальный адаптер.
4. Установить его через штатный импортёр Ports1de.
5. Проверить лог загрузки.
6. Только после этого подключать игровые события, Pawn/Map и UI.
