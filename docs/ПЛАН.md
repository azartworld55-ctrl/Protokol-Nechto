# План разработки

Статус: предварительный план. Целевая платформа — **RimWorld Android 1.7 через Ports1de**. Совместимость не считается подтверждённой, пока не проверены фактическая сборка порта и устройство.

## Этап 0 — техническая разведка Ports1de
- [ ] Зафиксировать точную версию Ports1de и RimWorld на целевом устройстве.
- [ ] Получить доступные исходники/документацию порта и выяснить загрузчик модов.
- [ ] Проверить версии runtime, managed DLL, Harmony и доступность игровых API.
- [ ] Определить ограничения Android: файловая система, производительность, память, сенсорный ввод и масштаб UI.
- [ ] Проверить лицензии и происхождение сторонних компонентов.
- [ ] Собрать минимальный тестовый мод и проверить его загрузку на устройстве.

## Этап 1 — минимальный каркас
- [ ] Создать и проверить загружаемый пакет «ПРОТОКОЛ: НЕЧТО» после подтверждения runtime.
- [ ] Добавить безопасное логирование и переключатель отладки.
- [ ] Зафиксировать инструкцию установки и тестирования.

## Этап 2 — управление и камера
- [ ] Прототип выбора одного персонажа.
- [ ] Камера следует за выбранным персонажем.
- [ ] Проверить прямое управление на сенсорном экране.
- [ ] Проектировать интерфейс под касания пальцами, не под геймпад.
- [ ] Не менять стандартное управление Ports1de до проверки прототипа.

## Этап 3 — обзор и карта
- [ ] Ограничить видимость обзором персонажа и препятствиями.
- [ ] Разделить известную планировку и актуальную видимую информацию.
- [ ] Проверить, что невидимые NPC продолжают симуляцию без раскрытия их действий игроку.

## Этап 4 — жители и социальная симуляция
- [ ] Интегрировать детерминированный генератор 12 жителей и квоты профессий из Draft PR #4 / интеграционной линии PR #6.
- [x] Независимая JSON-конфигурация квот и детерминированное распределение ровно 12 назначений.
- [x] Generic ProfessionRosterComposer применяет 12 назначений к упорядоченному ростеру.
- [x] Симметричные отношения с отдельными шкалами доверия и знакомства.
- [x] Личная память с проверкой владельца, дедупликацией событий и неизменяемыми снимками.
- [x] Передача слухов только через явное событие разговора, с конфигурируемым затуханием достоверности.
- [ ] Провести ревью и интегрировать Draft PR #6; добавить end-to-end тесты всего ростера в основной линии.
- [x] Независимый модуль потребностей, расписаний и выбора абстрактных действий для 12 жителей — `Protocol.Autonomy`; он использует `ResidentId` из Social и пока не зависит от Core.
- [ ] Диалоги, забывание, переоценка воспоминаний и конфликты.

## Этап 5 — паразит
- [ ] Ровно один паразит на партию.
- [ ] Самостоятельное наблюдение и выбор цели только из полученной информации.
- [ ] Ограничение нападения ситуацией без свидетелей.
- [ ] Копирование внешности, имени и социальной роли жертвы.
- [ ] Перенос воспоминаний жертвы с проверкой непротиворечивости.

## Этап 6 — расследование и последствия
- [ ] Система наблюдений и подозрений без безошибочного индикатора.
- [ ] Обвинения и социальные последствия.
- [ ] Арест за преступления против невиновных.
- [ ] Возможность побега из-под стражи.
- [ ] Продолжение игры за другого живого персонажа после гибели игрока.

## Этап 7 — сценарий и полировка
- [ ] Большая готовая база с функциональными помещениями.
- [ ] Бытовые и природные опасности.
- [ ] Несколько концовок без фиксированного лимита дней.
- [ ] Профилирование производительности и длительное тестирование на Android.

## Правило разработки

Каждый этап должен иметь маленький проверяемый результат. Не переносить сторонний код без подтверждённой лицензии, происхождения и совместимости. Не предполагать наличие API Ports1de. Все будущие интерфейсы проектировать mobile-first и под сенсорное управление.
