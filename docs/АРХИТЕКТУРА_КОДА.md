# Архитектура доменного ядра

## Срез состояния на 20 ноября 2026 года

Этот документ описывает чистую доменную линию проекта «ПРОТОКОЛ: НЕЧТО». Она отделена от другого проекта в репозитории — Prison Colony.

## Границы и зависимости

- `Protocol.Determinism` содержит SplitMix64, bounded sampling, стабильные Guid и Fisher–Yates.
- `Protocol.ProfessionConfig` валидирует явные квоты и детерминированно распределяет ровно двенадцать назначений; он использует `Protocol.Determinism`.
- `Protocol.Core` создаёт неизменяемый `StationRoster` из двенадцати `Resident`; он использует `Protocol.Determinism` и `Protocol.ProfessionConfig`.
- `Protocol.Social` использует `Protocol.Core` только на границе `StationSocialState`; обратной ссылки из Core на Social нет.
- `Protocol.StationIntegration.Tests` проверяет совместную работу генератора и социального состояния.

Зависимости направлены от доменных модулей к более базовым библиотекам; циклических ссылок между Core и Social нет.

## Генерация ростера

`StationRosterGenerator` создаёт ровно 12 профилей с уникальными ID и именами, возрастом, пятью параметрами личности, привычками, особенностями и профессиями. Профессии назначаются только из обязательной `ProfessionQuotaConfiguration`; встроенных игровых квот нет.

Генерация воспроизводится при фиксированных seed и конфигурации. Внутренний ID паразита отделён от публичного списка профилей и не совпадает с ID игрока. Это только маркер роли в ростере: поведения паразита и всеведения нет.

## Социальное состояние

`StationSocialState` принимает готовый `StationRoster`, создаёт двенадцать личных журналов и связывает `Resident.Id` с `ResidentId` через один Guid. `ResidentSocialView` предоставляет владельцу доступ к его памяти, парным отношениям и явной передаче слухов. Общего публичного перечисления всех журналов нет.

`RelationshipLedger` хранит симметричные Trust и Familiarity. `MemoryJournal` хранит прямые наблюдения и слухи, проверяет владельца, дедуплицирует события и поддерживает повышение слуха до прямого наблюдения. `RumorTransmissionService` работает только с явным `ConversationEvent` и обязательной политикой передачи.

## Проверки

- `Protocol.Core.SmokeTests`: PRNG vectors, границы модели, точные квоты, уникальность, read-only коллекции, golden snapshot и воспроизводимость.
- `Protocol.Social.Tests`: отношения, память, provenance и затухание слухов.
- `Protocol.StationIntegration.Tests`: генерация двенадцати жителей → двенадцать социальных views → наблюдение → два явных пересказа.
- GitHub Actions собирает Core и Social в Release с nullable analysis и предупреждениями как ошибками.

## Что не подключено

- Нет RimWorld, Verse, Unity, Harmony или Ports1de ссылок.
- Нет игрового адаптера, загрузочного пакета Protocol с About.xml/Assemblies и проверки DLL.
- Нет сохранения через RimWorld Scribe или другого versioned DTO.
- Нет расписаний, потребностей и автономного поведения NPC в этой чистой линии.
- Нет интерфейса расследования и mobile-first touch UI.
- Нет поведения паразита, магического всеведения или глобального доступа к памяти.

## Следующий шаг

По плану проекта следующая крупная доменная задача — расписания, потребности и автономное поведение NPC. Перед ней следует сохранить текущие инварианты интеграционными тестами. Игровой адаптер и сенсорный UI остаются заблокированы до подтверждения runtime, managed DLL и загрузчика конкретной сборки Ports1de.
