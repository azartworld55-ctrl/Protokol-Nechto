# Архитектура первого прототипа

## Почему код разделён на ядро и игровой адаптер

Целевая платформа проекта — Ports1de. Однако точные API и способ загрузки C#-сборок в установленной сборке Ports1de ещё не подтверждены.

Поэтому первый код вынесен в независимую библиотеку `Protocol.Core`: она не ссылается на RimWorld, Waylith, Unity или Harmony. Это позволяет проверять базовые правила обычной сборкой .NET и тестами на GitHub Actions.

Когда будут подтверждены игровые сборки и API Ports1de, появится отдельный адаптер, связывающий ядро с объектами RimWorld.

## Уже реализовано

- Модель жителя с проверкой входных данных.
- Личностные параметры: любопытство, общительность, осторожность, эмпатия и дисциплина.
- Набор повседневных привычек, не отменяющих реакцию NPC на срочные события.
- Детерминированная генерация стартовой группы из 12 жителей по seed.
- Ровно один идентификатор паразита на группу.
- Игрок назначается только одному из 11 человеческих жителей.
- Проверка состава группы и запрет назначать игрока паразитом.
- Социальные связи с независимыми шкалами доверия и знакомства.
- Личный журнал наблюдений и услышанных слухов.
- Снижение достоверности при пересказе слуха.
- Smoke tests для основных инвариантов.
- CI: проверка XML метаданных, сборка ядра и запуск smoke tests.

## Пока не реализовано

- Автономные расписания и выбор повседневных действий жителей.
- Передача слухов между конкретными жителями с учётом контакта и доверия.
- Изменение отношений в ответ на события.
- Игровой UI и камера.
- Поле зрения и интеграция с картой.
- Сохранение данных через механизм RimWorld.
- Игровой адаптер Ports1de.

## Следующий шаг

Добавить модель социальных событий и ограниченную передачу слухов: житель может пересказать только то, что сам наблюдал или услышал; достоверность зависит от источника и цепочки пересказов. Затем связать события с изменениями доверия. Не подключать игровые API, пока не подтверждены реальные DLL и runtime целевой сборки.
