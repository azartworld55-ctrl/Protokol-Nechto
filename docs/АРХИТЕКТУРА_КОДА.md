# Архитектура первого прототипа

## Почему код разделён на ядро и игровой адаптер

Целевая платформа проекта — Ports1de. Однако точные API и способ загрузки C#-сборок в установленной сборке Ports1de ещё не подтверждены.

Поэтому первый код вынесен в независимую библиотеку `Protocol.Core`: она не ссылается на RimWorld, Waylith, Unity или Harmony. Это позволяет проверять базовые правила обычной сборкой .NET и тестами на GitHub Actions.

Когда будут подтверждены игровые сборки и API Ports1de, появится отдельный адаптер, связывающий ядро с объектами RimWorld.

## Уже реализовано

- Модель жителя с проверкой входных данных.
- Личностные параметры: любопытство, общительность, осторожность, эмпатия и дисциплина.
- Набор повседневных привычек, не отменяющих реакцию NPC на срочные события.
- Детерминированная генерация стартовой группы из 12 жителей по seed.
- Ровно один идентификатор паразита на группу.
- Игрок назначается только одному из 11 человеческих жителей.
- Проверка состава группы и запрет назначать игрока паразитом.
- Социальные связи с независимыми шкалами доверия и знакомства.
- Личный журнал наблюдений и услышанных слухов.
- Передача слуха только после явного социального контакта, без глобальной рассылки.
- Вероятность передачи и достоверность слуха зависят от отношений.
- Защита от повторной передачи уже известного события одному жителю.
- Типизированные социальные события и правила их влияния на доверие и знакомство.
- Запись события в личные журналы участников и свидетелей; событие не становится автоматически известно всей станции.
- Реакции отношений применяются только для жителя, который действительно узнал о событии.
- Передача слуха может изменить отношение получателя к участнику события; слух остаётся помечен слухом и имеет сниженную достоверность.
- Состояние потребностей жителя: голод, усталость, потребность в общении и стресс.
- Выбор следующего действия на основе потребностей, времени суток, личности, привычек, отношений и личных воспоминаний.
- Часовой шаг симуляции, обновляющий потребности и назначающий автономные действия жителям.
- Smoke tests для основных инвариантов.
- CI: проверка XML метаданных, сборка ядра и запуск smoke tests.

## Пока не реализовано

- Полноценные расписания с рабочими сменами и конкретными местами/задачами на карте.
- Система видимости и реального определения свидетелей по геометрии карты; сейчас свидетели передаются ядру вызывающей стороной.
- Диалоги и генерация текстовых реплик.
- Долгосрочное забывание, вытеснение и переоценка воспоминаний.
- Многократное автономное распространение слухов между NPC по расписанию общения.
- Игровой UI и камера.
- Поле зрения и интеграция с картой.
- Сохранение данных через механизм RimWorld.
- Игровой адаптер Ports1de.

## Следующий шаг

Добавить календарные рабочие смены и планирование задач по профессиям, затем — модель контактов, которая будет определять, кто физически мог поговорить с кем. После этого можно подключать карту и поле зрения через отдельный игровой адаптер. Не подключать игровые API, пока не подтверждены реальные DLL и runtime целевой сборки.
