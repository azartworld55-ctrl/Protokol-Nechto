# Конфигурация квот профессий

Статус: независимый модуль конфигурации; подключение к генератору жителей выполняется отдельно.

## Зачем

В партии всегда 12 жителей. Профессии должны распределяться по явно заданным квотам, а не по случайному выбору из списка и не по придуманному разработчиком распределению.

В проекте намеренно нет встроенного набора квот. Пока состав профессий и их количество не утверждены, конфигурация должна быть предоставлена явно.

## Формат

JSON-файл версии схемы 1:

```json
{
  "schemaVersion": 1,
  "quotas": [
    { "professionId": "profession-id-from-game-design", "count": 12 }
  ]
}
```

Этот пример показывает форму документа, а не предлагает назначить всем жителям одну профессию. Реальная конфигурация должна содержать утверждённые идентификаторы профессий и такие количества, сумма которых равна 12.

JSON Schema находится в `config/profession-quotas.schema.json`. Она проверяет структуру и типы. Дополнительные проверки в C# проверяют сумму, положительные значения, отсутствие пустых ID и дубликатов без учёта регистра.

## Использование

```csharp
var configuration = ProfessionQuotaJson.Deserialize(jsonText);
var assignments = new ProfessionQuotaAllocator().Allocate(configuration, seed);
```

`assignments` содержит ровно 12 идентификаторов профессий. Порядок перемешивается детерминированным Fisher–Yates с собственным SplitMix64 PRNG. Одинаковые конфигурация, порядок квот и seed дают одинаковый результат; изменение seed меняет порядок, не нарушая количество каждой профессии.

Конфигурация и её список квот копируются при создании и не зависят от дальнейших изменений исходной коллекции. Неизвестные JSON-поля, повторяющиеся поля и неизвестные версии схемы отклоняются, чтобы опечатка не превращалась в тихое изменение баланса.

## Границы ответственности

- Модуль распределяет только идентификаторы профессий. Он не назначает навыки, рабочие места, смены или приоритеты.
- Модуль не содержит значений по умолчанию и не решает за автора игры, сколько должно быть врачей, инженеров или исследователей.
- Подключение результата к `StationRosterGenerator` из PR №1 остаётся отдельным интеграционным шагом. Этот ежедневный PR создан от актуального `main` и намеренно не копирует незавершённую ветку другого PR.
- Ни один API RimWorld, Unity, Harmony или Ports1de не используется. Чтение конфигурации из каталога мода и мобильный UI требуют подтверждённого игрового адаптера.

## Проверки

Проект `tests/Protocol.ProfessionConfig.Tests` проверяет точное количество 12, сумму квот, дубликаты, пустые и отрицательные значения, неизвестные JSON-поля/версии, round-trip JSON и фиксированную последовательность распределения для seed 417.

Тестовая раскладка синтетическая и используется только как fixture. Она не является балансным решением проекта.

## Источники и лицензии

Код модуля написан для этого репозитория с нуля. Сторонние исходники не копировались и не включались. Используются только стандартные библиотеки .NET, включая `System.Text.Json`; внешние NuGet-пакеты не добавлены.
