# Конфигурация квот профессий

Статус: независимый модуль конфигурации и композиции; в ежедневной ветке daily/2026-11-18 composer подключён непосредственно к чистому StationRosterGenerator.

## Зачем

В партии всегда 12 жителей. Профессии должны распределяться по явно заданным квотам, а не по случайному выбору из списка и не по придуманному разработчиком распределению.

В проекте намеренно нет встроенного набора квот. Пока состав профессий и их количество не утверждены, конфигурация должна быть предоставлена явно.

## Формат

JSON-файл версии схемы 1:

```json
{
  "schemaVersion": 1,
  "quotas": [
    { "professionId": "profession-id-from-game-design", "count": 12 }
  ]
}
```

Этот пример показывает форму документа, а не предлагает назначить всем жителям одну профессию. Реальная конфигурация должна содержать утверждённые идентификаторы профессий и такие количества, сумма которых равна 12.

JSON Schema находится в `config/profession-quotas.schema.json`. Она ограничивает число записей и каждую отдельную квоту диапазоном 1–12, запрещает пустые/пробельные ID и неизвестные поля. C#-валидатор дополнительно проверяет сумму, отсутствие дубликатов ID без учёта регистра, целочисленные границы и повторяющиеся JSON-свойства. Сумму и уникальность массива схема описывает не полностью; эти инварианты проверяются доменной моделью.

## Использование

Сначала десериализуется и проверяется явная конфигурация:

```csharp
var configuration = ProfessionQuotaJson.Deserialize(jsonText);
var assignments = new ProfessionQuotaAllocator().Allocate(configuration, seed);
```

`assignments` содержит ровно 12 идентификаторов профессий. Порядок перемешивается детерминированным Fisher–Yates с собственным SplitMix64 PRNG. Одинаковые конфигурация, порядок квот и seed дают одинаковый результат; изменение seed меняет порядок, не нарушая количество каждой профессии.

Если генератор уже создал 12 жителей, `ProfessionRosterComposer` применяет назначения к ним по индексам и возвращает новый read-only список:

```csharp
var composedResidents = new ProfessionRosterComposer().Compose(
    generatedResidents,
    configuration,
    seed,
    static (resident, professionId) =>
        resident with { ProfessionId = professionId });
```

Пример callback подходит для immutable record-модели. Для обычного класса callback должен создавать новый экземпляр жителя, сохраняя его ID, имя, возраст, личность, привычки и прочие поля, а меняя только профессию. Composer проверяет и заявленный Count, и фактическое перечисление: отклоняет короткие/длинные пользовательские реализации IReadOnlyList, ограничивает снимок двенадцатью элементами и проверяет null до вызова callback. Он сохраняет порядок исходных жителей и не меняет переданную коллекцию. Сам callback должен соблюдать неизменяемость объектов: generic API не может запретить ему мутировать входной объект.

## Границы ответственности

- Модуль распределяет только идентификаторы профессий. Он не назначает навыки, рабочие места, смены или приоритеты.
- Модуль не содержит значений по умолчанию и не решает за автора игры, сколько должно быть врачей, инженеров или исследователей.
- `ProfessionRosterComposer` — независимый мост между списком уже созданных жителей и распределителем квот. Он не зависит от типов `Protocol.Core`, RimWorld, Unity, Harmony или Ports1de.
- Прямая интеграция реализована в отдельной чистой модели Protocol.Core на ветке daily/2026-11-18. Она не импортирует код или историю PR №1. PR №1 остаётся отдельной незавершённой веткой; его социальные подсистемы не считаются частью этой реализации.
- Чтение файла из каталога мода и мобильный UI требуют подтверждённого игрового адаптера.

Конфигурация и её список квот копируются при создании и не зависят от дальнейших изменений исходной коллекции. Снимок ограничен двенадцатью элементами: поскольку каждая квота положительна, более длинный список не может быть допустимым. Коллекция перечисляется явно, без доверия к пользовательской реализации `ICollection.CopyTo`. JSON-десериализатор также отклоняет тринадцатую запись до добавления её в рабочий список. Публичные коллекции выдаются только для чтения. Неизвестные JSON-поля, повторяющиеся поля и неизвестные версии схемы отклоняются, чтобы опечатка не превращалась в тихое изменение баланса.

## Проверки

Проект `tests/Protocol.ProfessionConfig.Tests` проверяет точное количество 12, сумму квот, дубликаты, пустые и отрицательные значения, переполнение сумм, неизменяемость публичных коллекций, границы JSON, неизвестные поля/версии, round-trip JSON, крайние seed и фиксированную последовательность распределения. Дополнительно выполняется серия распределений по диапазону seed с проверкой точного совпадения квот.

Для composer проверяются точные квоты в готовом ростере, сохранение порядка и идентичности жителей, отсутствие изменения исходных записей, воспроизводимость полного результата, read-only коллекция, неверный размер, null-элементы, некорректный callback, однократный вызов callback, снимок до изменения исходной коллекции и несовпадение Count с фактическим перечислением.

Тестовая раскладка синтетическая и используется только как fixture. Она не является балансным решением проекта.

## Источники и лицензии

Код модуля написан для этого репозитория с нуля. Сторонние исходники не копировались и не включались. Используются только стандартные библиотеки .NET, включая `System.Text.Json`; внешние NuGet-пакеты не добавлены.
