# Генерация стартового ростера жителей

## Контракт

StationRosterGenerator создаёт ровно 12 жителей. Входом обязательно служит валидная ProfessionQuotaConfiguration; генератор не содержит списка профессий по умолчанию и не придумывает балансные количества.

Каждый житель получает:

- уникальный стабильный ID и уникальное имя из фиксированного пула;
- возраст в диапазоне 20–65 лет;
- пять независимых параметров личности в диапазоне 0–100: любознательность, общительность, осторожность, эмпатия и дисциплина;
- от одной до трёх неповторяющихся привычек;
- от одной до двух индивидуальных особенностей;
- профессию из распределения, которое точно соответствует переданным квотам.

Состав ростера и его коллекции неизменяемы снаружи. Модель не ссылается на RimWorld, Verse, Unity, Harmony или Ports1de.

## Воспроизводимость

StableRandom — общий SplitMix64 PRNG для доменной генерации и распределителя профессий. В нём зафиксированы константы, unbiased bounded sampling и Fisher–Yates. System.Random не используется.

При одинаковых seed и конфигурации получается одинаковый полный ростер: ID, имена, возраст, личность, привычки, особенности, профессии, ID игрока и скрытый ID паразита. Для генератора профиля и распределителя квот используются отдельные экземпляры PRNG с одним seed: изменение порядка квот не сдвигает поток личных характеристик.

Изменение пула имён, enum-значений или порядка вызовов случайного генератора изменит последовательность. Поэтому такие изменения требуют обновления тест-векторов и осознанного изменения контракта генерации.

## Профессии

StationRosterGenerator передаёт временные профили жителей в ProfessionRosterComposer. Composer назначает каждому профилю ровно один элемент заранее распределённого списка и создаёт новый immutable Resident. Входные профили не мутируются, порядок ростера сохраняется.

Тестовая конфигурация использует синтетические ID test-profession-* только для проверки инвариантов. Она не является рекомендуемым или утверждённым распределением для игры.

## Игрок и паразит

Ростер хранит ID игрока и отдельный ID паразита. Они обязаны принадлежать ростеру и не могут совпадать. ID паразита не включён в публичные свойства профиля жителя; он остаётся внутренним для доменной симуляции. На этом этапе нет ИИ паразита, скрытого всеведения, убийств, копирования или игровых эффектов.

## Проверки

tests/Protocol.Core.SmokeTests проверяет:

- точное число 12, уникальность ID и имён;
- допустимые диапазоны возраста и личности;
- количество и уникальность привычек и особенностей;
- точное совпадение количества профессий с каждой квотой;
- принадлежность игрока/паразита ростеру и их различие;
- полную воспроизводимость по seed и изменение результата при другом seed;
- стабильные тест-векторы SplitMix64;
- защиту read-only коллекций и копирование входного ростера;
- отказ для неправильного размера, дубликатов и некорректных значений.

Локальная сборка может быть недоступна в рабочей среде; авторитетная компиляция и smoke tests выполняются GitHub Actions на .NET 10. Это не утверждение о runtime Ports1de.
