# Социальное ядро и интеграция с ростером

Дата: 20 ноября 2026 года (Europe/Moscow)

## Область

`Protocol.Social` отвечает за симметричные отношения, личную память и передачу слухов. Он зависит от чистой модели `Protocol.Core`, но не зависит от RimWorld, Verse, Unity, Harmony или Ports1de.

`StationSocialState` создаётся из одного `StationRoster` и создаёт ровно один `MemoryJournal` для каждого из двенадцати жителей. Сопоставление выполняется по тому же Guid: `Resident.Id` → `ResidentId.Value`. Новые случайные ID при интеграции не генерируются.

## Отношения

- `RelationshipLedger` хранит одну запись на неупорядоченную пару: A↔B имеет одинаковые значения при чтении с обеих сторон.
- Trust и Familiarity — отдельные целочисленные шкалы 0–100.
- Изменения принимают `long` delta и безопасно насыщаются до границ без переполнения.
- Самоотношения и ID, отсутствующие в текущем ростере, запрещены.
- Пороговые значения передачи слухов задаются обязательной `RumorTransmissionPolicy`; игровые значения не зашиты.

## Личная память

- `StationSocialState` хранит журналы приватно и не предоставляет публичный список всех журналов.
- `ForResident(id)` возвращает `ResidentSocialView`, который показывает только память соответствующего владельца.
- Прямая запись проверяет владельца наблюдения и принадлежность наблюдателя/субъекта ростеру.
- Event ID дедуплицируется в журнале. Более позднее прямое наблюдение может подтвердить ранее услышанный слух того же события.
- `Memories` возвращает кешируемый read-only снимок; уже выданный снимок не меняется после новой записи.
- Это capability-style граница API, а не криптографическая изоляция внутри процесса: вызывающий слой должен выдавать конкретному NPC только его view и не запрашивать view другого NPC.

## Разговоры и слухи

- Передача требует явный `ConversationEvent`, оба участника которого принадлежат текущему ростеру.
- Близость, видимость или совместное нахождение на карте сами по себе не создают разговор.
- Отправитель может передать только событие из собственного журнала; получатель получает отдельную запись HeardRumor.
- Сохраняются первоначальный наблюдатель, последний информант, ID разговора, число пересказов и достоверность.
- На каждом пересказе применяется обязательный permille-множитель политики с округлением вниз.
- Повторное получение одного event ID тем же жителем не создаёт дубликат.

## Сквозной тест

`Protocol.StationIntegration.Tests` генерирует двенадцать жителей из синтетической конфигурации квот, строит социальное состояние, проверяет соответствие двенадцати Guid, симметрию отношений, изоляцию личных журналов и цепочку двух явных разговоров с затуханием 1000→750→562.

Синтетические значения в тесте не являются утверждённым игровым балансом.

## Ограничения

- Журналы пока не имеют политики забывания, ограничения размера или архивирования.
- Нет versioned DTO и сериализации/восстановления социального состояния.
- Модель рассчитана на последовательное обновление; потокобезопасность не заявляется.
- Генератор создаёт внутренний ID паразита, но не реализует его поведение, всеведение или доступ к памяти других жителей.
- Слой восприятия и симуляции обязан передавать только подтверждённые наблюдения и реальные события общения.
