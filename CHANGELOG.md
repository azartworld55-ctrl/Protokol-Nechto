# Changelog

## 2026-11-20 — Сквозная интеграция ростера и социального состояния

- Перенесён в актуальную линию чистый `Protocol.Core`: ровно 12 жителей, уникальные ID/имена, возраст, личность, привычки, особенности и обязательные квоты профессий.
- `Protocol.Determinism` вынесен в общий модуль SplitMix64; генератор и распределитель квот используют стабильный PRNG без `System.Random`.
- `Protocol.Social` теперь зависит от Core в одном направлении и создаёт `StationSocialState` для конкретного ростера.
- Добавлен `ResidentSocialView`: каждый view показывает только память своего владельца; нет публичного перечисления всех журналов.
- Добавлены сквозные проверки 12 GUID, точных синтетических квот, симметрии отношений, изоляции памяти и цепочки слухов через два явных разговора.
- Реальные квоты профессий не утверждались; значения integration-alpha/beta/gamma используются только в тестах.
- Игровые API, DLL, адаптер и Android UI не добавлялись; совместимость Ports1de не заявляется.
- Локальный .NET SDK отсутствует; сборка и тесты выполняются GitHub Actions.

## 2026-11-19 — Симметричные отношения, личная память и слухи

- Добавлен независимый `Protocol.Social`: симметричные отношения с отдельными шкалами доверия и знакомства, безопасное насыщение при экстремальных delta.
- Добавлен личный `MemoryJournal` с проверкой владельца, дедупликацией событий, кешируемыми неизменяемыми снимками и повышением слуха до прямого наблюдения при независимом подтверждении.
- Передача слухов возможна только между участниками явного `ConversationEvent`; каждая запись слуха сохраняет ID разговора, происхождение и затухание достоверности по обязательной политике.
- Регрессионные тесты покрывают симметрию отношений, overflow, приватность памяти, кеш снимков, прямое подтверждение слуха, временные границы и явное общение.
- Добавлен отдельный GitHub Actions workflow для социального домена.
- Значения затухания и порогов в тестах синтетические; игровые настройки не утверждались.
- Финальный аудит добавил регрессионные проверки повторного event ID с другим subject, несоответствия владельца журнала отправителя/получателя и пустого event ID.

## 2026-11-17 — Композиция ростера из квот профессий

- Добавлен независимый `ProfessionRosterComposer`: он применяет ровно 12 детерминированных назначений к существующему упорядоченному списку жителей, сохраняет порядок и возвращает read-only коллекцию.
- Проверка входного ростера использует ограниченный снимок через явное перечисление и не доверяет пользовательскому `ICollection<T>.CopyTo`.
- Конфигурация квот ограничивает число положительных записей двенадцатью; JSON-десериализатор отклоняет 13-ю запись до добавления в рабочий список.
- Добавлены регрессионные тесты для несовпадения Count/перечисления, некорректного CopyTo, изменения исходной коллекции, предельного числа квот и JSON-записей.
